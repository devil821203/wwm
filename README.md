# 燕雲十六聲國際服 DPS 模擬器 — Codex 管理式開發專案

目前 **S01–S13（Web 基礎、資料治理、角色裝備、OCR、數值／實測、Worker 模擬、裝備生成與最佳化）已完成，完整遊戲模擬器仍在開發中**。完整需求在 `requirements/`（V1.3），開發管理與紀錄在 `management/`。

## 開始

1. Codex 先讀 `AGENTS.md`、`management/overview/DEVELOPMENT-OVERVIEW.md`、`management/plans/STEP-PLAN.md` 與 `requirements/README.md`。
2. 依 `management/progress/STATUS.md` 找第一個可執行步驟；同時只處理一個步驟。
3. **先完成該步驟全部程式修改，然後集中測試**。失敗時修正並重跑該步驟相關測試，直至通過或因明確跨功能依賴而擱置。
4. 每輪更新進度、測試報告、問題單與決策紀錄；不得把未執行測試記為通過。
5. 所有遊戲數值：資料庫明確值優先；缺值可推估但 UI 明示預估；未知且無可用模型不得輸出 DPS。

## 本機開發（S01）

需求：Node.js 22.14+、pnpm 10.6.5。於專案根目錄執行：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd dev
```

開啟終端顯示的本機網址。建置後以 `pnpm.cmd preview` 查看正式產物。

若使用本次建立的專案內可攜工具鏈，先於 PowerShell 設定本次工作階段 PATH（不修改系統設定）：

```powershell
$env:Path = "$PWD\.tools\node-v22.14.0-win-x64;$PWD\.tools\pnpm\node_modules\.bin;$env:Path"
```

可攜工具鏈不納入版本控制；其他環境請安裝相容 Node 與指定 pnpm。

## 角色與本機備份（S04）

主選單「角色與配置」可新增／編輯／刪除角色，新增／修改／複製／刪除多套 Build，並保存至 IndexedDB。
無版本資料時可使用候選流派建立草稿，角色等級維持未知；有匯入版本時只提供該版本的合法等級、屬性與武學。
手動面板值保留確認證據與原始精度；面板是否已含裝備由使用者明確指定，供後續屬性合成使用。
使用「下載 JSON 備份」保存本機資料；「選擇 JSON 備份」先驗證並預覽，確認後合併。相同 ID 不同內容會拒絕整批，避免覆蓋現有角色。
資料只屬於目前網址與瀏覽器，不會自動同步到其他裝置；清除網站資料可能移除紀錄。舊版 owned/virtual 分庫範例不適用本備份格式。
角色版本與流派建角後固定；如需另一版本，請建立新角色。其他限制與交易設計見 ADR-005。

## 統一裝備庫（S05）

主選單「裝備庫」的手動與截圖入口共用同一編輯器。無版本、品質、階級或部位時仍可保存未驗證草稿，不必先分類。
數值需逐欄勾選人工確認；未確認或空白保留未知與原始輸入，0 和小數原值不會被補值或預先取整。
PNG/JPEG/WebP 圖片僅在本機預覽，每張最多 5 MB、每件最多 3 張。只有勾選保存同意才會寫入 IndexedDB 並包含在 JSON 備份中；不會上傳第三方。
既有裝備可編輯、複製、刪除及查看歷史。相同已知版本且部位確認後可加入配置，仍顯示待合法值驗證；同部位替換引用，不刪除庫中原件。
Dexie v2 保留既有 v1 角色資料並新增圖片／編輯歷史表，舊備份仍可匯入。本機 OCR 已於 S06 接入；S07 已提供依版本規則的合法滿值預覽及模式切換。

## 本機 OCR（S06）

裝備校對頁提供本機影像辨識及文字匯入兩種 adapter。影像引擎使用 Tesseract.js，worker、WASM與英語/繁中模型在dev/build時由鎖定套件準備到本站，不從CDN載入，也不傳玩家圖片給第三方。
可指定辨識範圍/旋轉/取樣倍率；原圖保持不變。辨識結果先列為候選，顯示原文、信心、辨識圖座標，明確加入後仍需逐欄人工確認。重辨識不覆蓋既有/手改數值。
百分比保留原百分數與單位，缺字/多義/範圍值保留未知。模型失敗時可改用文字候選或完整手動流程；文字匯入信心為未知，不冒充影像辨識。
OCR證據隨數值保留於備份，人工更正不刪除原始辨識值；影像是否保存仍依原圖同意選項。
開發/build資產準備指令：node tools/prepare-ocr-assets.mjs。產出apps/web/public/ocr-assets/manifest.json記錄hash/來源套件授權檔，生成檔不納入Git。完整安裝時需包含devDependencies中的語言模型。
目前驗證以合成fixture為準，不宣稱對真實遊戲截圖的辨識準確率；版本合法值規則引擎見 S07；正式遊戲資料與 DPS 仍待後續步驟。

## 版本化裝備數值與合法性（S07）

裝備編輯器可逐條選擇目前值、承音或當階滿值，並按「預覽有效值與合法性」比較原值、有效值及上限。承音優先保留已確認的實例覆寫，再查同條件資料庫值，缺值才用已登記模型；沒有通用94%或跨階級上限。每個推估值顯示「預估值」，可展開公式、參數、模型版本、日期與來源；「僅使用明確資料」會禁止估算。
品質基礎值依版本、部位、階級及品質唯一匹配，不借用其他品質。原始baseStats/current與觀察證據保留，有效值另外保存；MAX只改預覽模式，不改原值。切換承音／MAX採單一選擇，明確選擇MAX才能解除同詞條衝突。
完整已驗證詞條池、數量、互斥、階段、上下限及步進資料齊全時，才啟用「填入已驗證合法滿值」。不合法可存草稿；資料不完整維持UNVERIFIED。儲存交易重新解析當前本機版本，舊備份仍可匯入，編輯歷史可還原原值。
目前沒有正式遊戲規則資料；引擎與UI以明示合成fixture驗收，不宣稱已具備真實遊戲合法完美裝備或DPS。詳細契約見ADR-008及game-data README。

## 屬性合成與單技能傷害（S08）

主選單「傷害與溯源」讀取本機角色配置，選擇此版本流派技能後計算。基礎面板另加裝備；已含裝備的面板不重複加總；面板語意未知則阻擋。缺少某屬性面板不自動填0。
結果顯示逐項屬性來源、公式版本、假設、必要未知與預估依賴；可切換「僅使用明確資料」。未使用的未知詞條不污染不依賴它的傷害。裝備自身的明確資料限制亦保留。
「下載此次計算紀錄」保存完整request/result JSON，含版本、角色/武學等級、配置、技能、公式、參數、裝備與固定計算時間；同一輸入可重現。畫面數字最多顯示10位有效數字，計算與下載紀錄保留原始精度。
獨立套件位於packages/stat-engine，提供aggregateStats及calculateDamage。只支援登記的weighted-hit-v1固定實作，所有倍率/機率均需明確提供；缺公式證據、技能適用範圍或必要輸入即無法計算。不執行JSON程式碼、不借用別流派係數。
目前數字驗收皆為明示合成fixture，不是遊戲實測公式。meanDps維持null，單技能傷害不換算成DPS；S09 已提供鳴金·虹實測契約；S10 已提供循環事件驗證，DPS 模擬依 S11 開發。

## 鳴金·虹技能變體與實測（S09）

主選單「實測紀錄」可選鳴金·虹配置，輸入固定敵人、狀態／施放流程、來源及原始傷害樣本。需求預設武學為無名劍法＋無名槍法，實際ID、技能名與數值由所選版本提供；未提供真實技能清單或係數時明示缺失，不補值。
版本技能可宣告普通／蓄力等變體，各自有係數、命中時間、蓄力、劍氣及切換／狀態事件描述。有變體時必須明確選擇，傷害頁不會回退別的變體或父技能係數。事件描述可由 S10 的完整版本戰鬥規則接入執行；缺少規則時不補值。
單技能觀察每筆為一次完整施放總傷害；只有未篩選樣本且明確確認條件符合公式假設，才比較期望值並提供MAE、MAPE百分比及零分母排除數。報告標示「觀察比較，未校準」，未設定任意通過門檻，不會自動反推或覆寫係數。
60秒模式每筆保存完整60000ms的總傷害觀察，尚無循環模擬預測或DPS。截圖參照只記錄檔名／來源，不自動保存圖片。
Dexie v3新增實測表，保留角色／裝備／圖片／歷史。快照包含固定版本、角色、配置、裝備與公式；不可覆寫，修正時另存新紀錄。刪除原角色不刪歷史快照；玩家JSON備份包含實測，舊備份仍可匯入。
目前只有合成fixture驗收，沒有真實係數或三組遊戲實測，不宣稱已校準或準確率達標。

## 循環事件驗證（S10）

主選單「循環驗證」可編輯固定時間動作或由上至下的優先序規則，明確選擇初始武學、技能變體與決策間隔。循環保存在Build內，沿用配置複製、過期編輯拒絕及玩家JSON備份；保存草稿不等同通過驗證。
戰鬥規則必須來自相同版本：施放時間、冷卻起點與共用群組、資源變化、Buff倍率/持續時間、DOT間隔/持續時間/快照與重套用規則。未知必要值不填0，不借父技能或其他變體；可切換僅使用明確資料。
時間為整數毫秒，事件按時間與加入序號排序；同時刻的既有動作會先於其後新增事件。時間窗及Buff/DOT有效區間為起點含、終點不含，到期毫秒先失效。施放時間已含蓄力，不會重加；資源整批檢查後才扣用。
輸出事件明細、來源、最終資源/武學與期望總傷害，違規或未知時總傷害為null，部分事件僅作診斷。最長時間窗3600000ms，每次最多處理10000事件；畫面最多顯示200筆，下載完整循環紀錄保存實際request/result。
目前只有明示合成fixture，沒有遊戲實測校準。S10不提供DPS或Monte Carlo，meanDps維持null；Worker、圖表與DPS由S11接續。

## S11 模擬中心

先在「循環驗證」保存 Build 的固定或優先序循環，再到「模擬中心」選配置。可選期望值或 Monte Carlo、uint32 seed（包含0）及1–10000樣本；使用獨立 Web Worker，顯示進度且可取消，改條件或離開頁面會停止舊任務。

期望DPS以完整循環總傷害除以完整時間窗；Monte Carlo逐命中抽普通／會心／會意／失誤，Buff與DOT沿用事件核心。版本化敵人倍率保留於公式參數與下載快照，不預設敵人防禦或等級倍率。技能命中／DOT占比與累積傷害圖使用期望模式，抽樣結果另列平均、標準差及95%常態近似平均區間；此區間不能當作遊戲模型的可信度。

必要資料、循環或裝備合法性缺失時不輸出DPS。任一必要推估依賴傳遞「包含預估資料」，可啟用「僅使用明確資料」。下載JSON保留完整輸入、seed、演算法版本、來源、樣本及完整時間線。合成資料永遠標示非真實遊戲DPS；目前尚無真實係數、規則與三組遊戲實測的準確率證明。

## S12 理想裝備工坊

「裝備庫」內提供當階滿值候選、指定詞條、固定seed隨機候選及既有裝備微調。先選版本裝備定義、角色合法等級與調律階段，確認模擬用途後預覽。品質基礎值、詞條池、數量、互斥、當階上下限與步進均依版本資料；缺少完整規則時說明原因，可回到原手動編輯器保留未知草稿。

滿值模式枚舉合法詞條組合（最多24種詞條、20000搜尋節點、256候選），截斷時明示不完整。這些是未排名的滿值候選，由下節S13在本次候選範圍評分與判定最優性，不將第一件稱作全域完美。隨機模式只在完整有限組合中均勻選擇；「指定數值／隨機步進值」再從已驗證網格取樣，其他模式使用選定MAX／承音值，非真實掉落率。

指定或隨機的數字是使用者確認的模擬設定，保留scenario稽核ID與「非遊戲實測」註記；不冒充資料庫明確實測值。MAX使用資料庫上限原來源；承音仍由既有引擎優先查明確值，缺值才依版本模型推估，每欄顯示「預估值」。精度/必要值不齊維持UNVERIFIED，僅使用明確資料會阻擋估算。

候選開啟同一裝備編輯器，保存至統一裝備庫，creationMethod=GENERATED不改變計算路徑。微調只修改勾選詞條，原件保留，副本以derivedFromId關聯；原圖不隱式複製。保存交易重新解析目前規則。入庫後加入同版本Build，再按「以此配置前往模擬中心」；未有循環、公式或合法性證據時仍不輸出DPS。生成稽核與原件關聯隨玩家JSON備份保存，不另建虛擬庫存。

## S13 裝備最佳化

主選單「裝備最佳化」選取已保存循環、BASE_ONLY基礎面板的Build。選定搜尋部位、可選鎖定裝備、排除候選、自訂成本上限、最低屬性與已登記套裝件數，設定Top-K後啟動。已含裝備的面板無法可靠反推出換裝後基礎，因此不進行換裝最佳化。每個選定部位選一件；未選部位會從候選配置移除，原配置不變。

獨立packages/optimizer使用與模擬中心相同的完整期望循環。十件以下且組合數不超5000自動完整枚舉；其餘使用單技能代理分數的Beam Search，加兩輪單部位局部搜尋，最終排名使用完整循環DPS。代理分數不當DPS，未知不當0。畫面提供候選裝備、收益差、來源/預估依賴、探索量與覆蓋率。Beam、資料缺漏或搜尋截斷均顯示未證明最優；完整枚舉的證明也只限本次輸入合法候選與約束，不代表遊戲所有裝備或連續詞條的全域最優。

自訂成本是比較情境，不代表遊戲價格；啟用預算時缺值不能當0。套裝使用同版equipmentSets的已驗證靜態屬性門檻，不把缺少/未驗證效果當作無加成；達成門檻的數值保留ResolvedValue來源與估計標記。特殊未建模效果不可標為已驗證。套裝與裝備不在已含裝備面板中重複計入。

Worker回報進度並可取消，換配置、改條件或離開頁面會停止舊任務。最多500件/16部位、50000節點、5000次完整重算及Top20。下載最佳化快照保留完整request/result。選擇候選另存Build並前往模擬；保存前在交易內比對角色/配置/庫存/版本快照，重新驗證同約束與循環，有變更就要求重跑，原Build與裝備不覆寫。

本次工具鏈檢查發現既有依賴快取與檔案受損，已保留.tools/node-modules-s13-damaged並按鎖檔重建至.tools/pnpm-store-s13。此工作區重裝可使用pnpm.cmd install --frozen-lockfile --store-dir .tools/pnpm-store-s13；外部套件版本與完整性鎖定值未變更。

## S14 部分進度與阻塞

角色建立時顯示選定流派的版本資料缺口；流派可宣告必要處理器 ID，僅支援已實作的 weighted-hit-v1 / combat-events-v1，未支援機制會阻擋單技能及循環，包含空循環。11 個候選流派已有獨立合成公式／循環與未知或跨流派綁定阻擋測試；合成資料並非遊戲資料。
