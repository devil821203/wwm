# V1.3 數值來源與預估標記（最高優先規格）

## 核心規則
1. 對同一裝備／版本／階級／詞條／培養狀態的值，先查明確記錄的資料庫值；查無記錄時才可依已明確登記的推估模型計算；再無模型則為 UNKNOWN，不能填 0 或虛構。
2. 使用者輸入或截圖人工確認的實際值，是該裝備實例的覆寫值，不覆寫主資料庫。資料庫中如有衝突需顯示差異與來源。
3. 每一個推估數值旁必須顯示「預估值」，並可查看推估公式、參數、依據、遊戲版本、推估模型版本與日期。不得以顏色作為唯一標示。
4. 所有衍生數值（面板、技能傷害、DPS、最佳化排名）須傳遞來源狀態；只要依賴任一預估值，就顯示「包含預估資料」，並列出依賴項。必要數值 UNKNOWN 且無模型時，顯示「無法計算」及缺失項目，不得輸出貌似精確的 DPS。
5. 不要將資料庫存在的「估算紀錄」當成「明確實測值」。明確記錄需包含 value、source、gameVersion、status=RECORDED；如記錄自身為 ESTIMATED，仍以預估值標示。
6. 數值選擇的優先順序：已確認的裝備實例手動值 > 同條件的明確記錄值 > 同條件的版本化推估模型 > UNKNOWN。若使用者明確選擇模擬滿值，則使用對應滿值模式，不應無意間覆寫現有實際值。

## 裝備特殊規則
- 紫裝：依品質對應的實際基礎屬性查表，缺值可推估但需標示。
- 承音：先查同版本／階級／詞條／承音狀態的明確承音數值；查無才採有版本及階級範圍的係數推估（例如 0.94 只能作為暫定模型，不能無條件通用）。承音目前值與培養上限分開。
- 調律滿值：先查同版本／階級／詞條的明確理論最大值；查無才推估並標示。
- 不因裝備由截圖、手動或生成而改變計算公式；所有裝備共用資料模型。

## 建議型別
```ts
type ValueStatus = 'MANUAL_CONFIRMED' | 'RECORDED' | 'ESTIMATED' | 'UNKNOWN';
interface ResolvedValue {
  value: number | null;
  status: ValueStatus;
  sourceId?: string;
  gameVersion: string;
  formulaId?: string;
  modelVersion?: string;
  inputs?: string[];
  note?: string;
}
interface ResultProvenance {
  containsEstimates: boolean;
  blockingUnknowns: string[];
  estimatedDependencies: string[];
  recordedDependencies: string[];
}
```
注意：數值 `0` 是合法值，不能用 truthy 判斷是否缺值。保留百分比原始精度與顯示精度，不可先四捨五入再計算。

## UI 規則
- 裝備編輯器每個欄位顯示「手動輸入／資料庫數值／預估值／未知」之一。
- 點選預估值可檢視計算方式、參數、來源與版本；可人工修正，修正後標記為手動輸入。
- DPS 與最佳化結果顯示是否包含預估資料；最佳化候選必須使用相同版本與情境；不能把 UNKNOWN 當 0 排名。
- 提供「僅使用明確資料」篩選；開啟後禁止預估，無法計算時顯示缺失原因。

## 驗收測試
1. 有資料庫承音明確值時使用明確值，不執行 94% 推估。
2. 無明確值、有適用版本模型時推估，欄位顯示「預估值」及公式來源。
3. 無明確值、無模型時 UNKNOWN，不輸出 DPS。
4. 人工確認值覆寫該裝備實例，不改主資料庫。
5. 任一依賴值為 ESTIMATED，DPS 顯示「包含預估資料」。
6. 未使用的詞條是 UNKNOWN，不應污染不依賴它的結果。
7. 理論滿值與裝備當前值分開，不因切換預覽而覆蓋實際值。
8. 已記錄值為 0 時仍正確識別為 RECORDED。
9. 截圖 OCR 未經確認的值不得標示為 MANUAL_CONFIRMED。
10. 僅使用明確資料模式下，不進行任何推估。
